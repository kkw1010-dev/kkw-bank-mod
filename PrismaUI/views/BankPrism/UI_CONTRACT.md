# BankView.html 인터페이스 계약

이 폴더의 `BankView.html`은 게임과 두 방향으로 통신한다. **모양은 얼마든지 바꿔도
되지만, 아래 계약을 깨면 UI가 아니라 모드 전체가 동작하지 않는다.**

디자인만 손보는 경우 이 문서의 내용만 지키면 되고, Papyrus나 C++는 건드릴 필요가
없다.

## 1. 게임 → UI

게임이 이 함수를 호출한다. **이름을 바꾸면 안 된다.**

```js
window.bankUpdateParams(jsonString)
```

넘어오는 JSON의 필드는 다음과 같다. 전부 매번 들어온다.

| 필드 | 형 | 의미 |
| --- | --- | --- |
| `wallet` | 정수 | 플레이어 소지금 |
| `balance` | 정수 | 이 홀드에 맡긴 금액 |
| `debt` | 정수 | 이 홀드의 대출 잔액 |
| `creditDebt` | 정수 | 이 홀드의 외상 잔액 |
| `loanLimit` | 정수 | 대출 한도. 0이면 대출 불가 |
| `creditLimit` | 정수 | 이 홀드의 외상 한도 |
| `tier` | 정수 | 신용등급 단계 1~5 |
| `loanDaysLeft` | 정수 | 만기까지 남은 일수. 음수면 지난 것 |
| `overdueDays` | 정수 | 연체 일수. 0이면 연체 아님 |
| `grade` | 문자열 | 등급명. 아래 12개 중 하나 |
| `hold` | 문자열 | 홀드 이름 (화이트런 등) |
| `holdKey` | 문자열 | 홀드의 ASCII 키 (`whiterun` 등). 그림 파일명이 전부 이 키를 쓴다 |
| `txType` | 문자열 | 방금 성사된 거래 종류. 없으면 빈 문자열 |
| `txAmount` | 정수 | 그 거래 금액 |
| `message` | 문자열 | 화면에 띄울 안내 문구 |

`txType`이 비어 있지 않을 때만 거래 기록에 한 줄을 추가한다. 값은
`deposit` / `withdraw` / `borrow` / `repay` / `payCredit` 중 하나다.

### 등급명과 단계

등급은 행적으로 얻는 계급이고, **한 번 오르면 내려가지 않는다.** 같은 단계라도
무엇으로 올랐는지에 따라 이름이 다르며, 게임이 보내는 값은 이 12개뿐이다.
`tier`가 함께 오므로 이름에서 단계를 역산할 필요는 없다.

| 단계 | 등급명 | 오르는 조건 |
| --- | --- | --- |
| 1 | 외지인 | 기본 |
| 2 | 정체모를 용병 | 대학 입학 · 컴패니언 가입 · 잡다한 목표 10 · 드래곤 라이징 · 내전 입대 |
| 3 | 영지의 종사 | 그 홀드의 세인 |
| 3 | 신뢰받는 해결사 | 잡다한 목표 30 |
| 4 | 스카이림의 영웅 | 알두인 1차 격퇴 (MQ206) |
| 4 | 요르바스크의 전사 | 컴패니언 서클 진입 |
| 4 | 수석 마법학자 | 대학 랭크 4 (Wizard) |
| 4 | 훈장 수훈 장교 | 내전 계급 2 |
| 5 | 탐리엘의 구원자 | 알두인 최종 처치 (MQ306) |
| 5 | 컴패니언의 인도자 | 하빈저 |
| 5 | 대학의 아크메이지 | 대학 랭크 6 |
| 5 | 전쟁 영웅 장군 | 내전 계급 4 |

`BankView.html`의 `GRADE_DATA` 키가 이 이름들과 정확히 같아야 한다. 이름을 바꾸려면
`BankPrismController.psc`의 `GetCreditGrade()`도 같이 바꾼다.

한도 숫자는 UI에 박아두지 말고 `loanLimit` / `creditLimit`을 그대로 쓴다. 실제 값은
`BankLoanLimitTier1~5`, `MerchantCreditLimitTier1~5` 글로벌에 들어 있다.

## 2. UI → 게임

버튼을 누르면 이 함수를 호출한다. **이름을 바꾸면 안 된다.**

```js
window.bankAction(payload)
```

`payload`는 문자열이며 두 가지 형식뿐이다.

```
"close"              금액이 없는 동작
"deposit:500"        금액이 필요한 동작은 콜론 뒤에 정수
```

보낼 수 있는 동작은 다음이 전부다. 이 외의 문자열은 게임이 무시한다.

| 동작 | 금액 | 의미 |
| --- | --- | --- |
| `deposit` | 필요 | 입금 |
| `withdraw` | 필요 | 출금 |
| `borrow` | 필요 | 대출 실행 |
| `repay` | 필요 | 대출 상환 |
| `payCredit` | 불필요 | 외상 상환 |
| `sellBond` | 불필요 | 채권 매각 (미구현) |
| `close` | 불필요 | 창 닫기 |

## 3. 반드시 남겨야 하는 것

- **`window.bankUpdateParams`와 `window.bankAction` 두 이름.** 게임이 이 이름으로
  찾는다
- **배경 이미지 경로는 `bg/<holdKey>.jpg` 상대경로.** 홀드마다 다른 그림이 깔린다
- **닫기 버튼.** `close`를 보낼 수단이 없으면 창을 닫지 못한다

## 4. 하면 안 되는 것

- **텍스트 입력창(`<input type="text">` 등)으로 금액을 받지 말 것.** 게임이
  일시정지된 상태에서는 키보드 입력이 이 화면에 전달되지 않는다. 금액은 버튼으로
  만든다
- **외부 리소스를 불러오지 말 것.** 폰트, CDN, 이미지 URL 모두 안 된다. 게임 안
  브라우저라 네트워크가 없다. 필요한 파일은 이 폴더에 두고 상대경로로 쓴다
- **`alert()`를 쓰지 말 것.** 렌더러에 없는 함수다. 안내는 화면 안에 표시한다
- **그림 파일 이름에 한글을 쓰지 말 것.** URL에 들어가는 이름은 전부 ASCII로 둔다.
  게임이 `holdKey`를 따로 보내는 이유가 이것이고, 게임 안에서는 그림이 안 뜨는
  이유를 확인할 방법이 없다. 현재 쓰는 이름은 다음과 같다:
  - 배경 `bg/<holdKey>.jpg`
  - 문양 `emblems/<holdKey>.png`
  - 청지기 초상화 `portraits/<holdKey>-t<단계>.jpg` (1~5)

  초상화는 아직 화이트런 것만 그려져 있고, 없는 홀드는 `onerror`로 화이트런 것을
  대신 쓴다. 한 홀드를 추가하려면 파일 다섯 장을 넣기만 하면 되고 JS는 건드릴
  필요가 없다

## 5. 고쳐도 되는 것

레이아웃, 색, 글꼴 크기, 탭 구성, 애니메이션, 요소의 `id`와 클래스 이름 —
**JS를 함께 고치는 한 전부 자유다.** `id`는 이 파일 안에서만 쓰이므로 게임과는
무관하다.

## 6. 고친 뒤에

저장소 최상위에서 배포 스크립트를 돌려야 게임에 반영된다.

```
powershell -File deploy.ps1
```

HTML만 고쳤다면 이것만 하면 되고, 게임은 다시 켜야 한다.
